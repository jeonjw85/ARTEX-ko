# 상황별 예산 책정으로 긴 대화 우회

2026-09-11 수정되었습니다. 원래 구현에서는 JSON에 대해 요청된 문자 수를 token로 직접 처리하고 주 작업의 32K 출력 예약을 상속하므로 HTML, JS 및 도구 결과가 많을 경우 정상적인 우회 문제가 미리 거부됩니다.

## 오픈소스 구현 검증

- [Grok CLI 우회 컨텍스트](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/agent.ts#L739): 최근 사용자 및 보조자 텍스트에서 조각을 추출합니다. 캐릭터 예산은 약 2000자 정도이며, 각 작품당 최대 400자를 가로챌 수 있습니다. 이 경로에서는 지속적인 우회 질문 및 답변 기록이 유지되지 않습니다.
- [Grok CLI 독립 요청] (https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/utils/side-question.ts): 독립 취소 신호; 모델이 지원하는 경우 출력 상한은 2048 tokens입니다. 도구는 제공되지 않습니다.
- [Grok CLI 기본 세션 압축](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/compaction.ts): token를 추정하고, 최신 콘텐츠를 유지하고, 새 콘텐츠를 이전 다이제스트로 업데이트하고, 교차 잘림을 처리합니다.
- [OpenCode 세션 압축] (https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/compaction.ts): 전체 요청 추정, 출력/버퍼 예약, 최신 콘텐츠 및 롤링 요약, 도구 없는 요약 요청; 이 구현의 기본값은 최근 예산 8000과 요약 출력 제한 4096 tokens입니다.
- [OpenCode 오버플로 복구](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/runner/llm.ts): 보조 출력이 시작되지 않은 경우에만 오버플로 복구가 시도됩니다. 복구 후 호출은 더 이상 동일한 오버플로 복구 경로에 들어가지 않습니다.

ARTEX는 독립적인 출력 예산, 최신 콘텐츠 및 롤링 다이제스트, 제한된 복구 방식을 활용합니다. norma v0.3.6의 구조화된 메시지와 도구 쌍을 유지하고 Grok의 텍스트 발췌 부분을 복사하지 마십시오. OpenCode의 기본 세션 압축 이벤트를 ARTEX 기본 transcript에 쓰지 마세요.

## 예산 및 집행요청

- 메시지는 norma 바이트 추정 및 콘텐츠 블록 UTF-8별 4/3 마진을 따릅니다. 추가 시스템 프롬프트, 도구 schema 및 메시지 캡슐화 오버헤드가 포함됩니다. 추정치는 모델의 정확한 token 개수가 아닙니다.
- 기본 바이패스 출력은 최대 8192 tokens이며, 이는 기본 구성에 의해 설정된 출력 상한을 초과하지 않습니다. 사용 가능한 서비스 환경 변수 `ARTEX_BTW_MAX_OUTPUT_TOKENS`는 상한을 256~32768로 설정합니다. 제품 기본 모델이나 기본 작업 매개변수는 수정되지 않습니다.
- 입력 예산은 컨텍스트 창에서 출력 상한 및 안전 마진을 뺀 값입니다. 알 수 없는 창은 플랫폼 기본값인 200K를 사용합니다. 안전 마진은 창의 5%, 최소 128, 최대 8192 tokens입니다.
- 각 배치에는 최대 20개의 성공적인 질문 및 답변 그룹을 오름차순으로 로드할 수 있습니다. 최대 20세트의 원본 텍스트가 유지되며 token 예산은 최대 입력 예산의 1/4이고 16K를 넘지 않습니다.
- 롤링 다이제스트에 대한 초과 구독 Q&A 업데이트입니다. 요약에는 과거 소스와 컨텍스트 시간이 포함됩니다. 역사 보조자의 답변은 새로운 도구 증거와 동일하지 않으며, 충돌이 발생할 경우 최신 마스터 스냅샷이 우선적으로 적용됩니다.
- 기본 컨텍스트가 여전히 너무 길지만 다이제스트 복사본의 오래된 메시지(최근 최대 8K tokens)만 유지됩니다. 차단 지점은 도구 호출과 결과를 분리하지 않습니다. 너무 큰 단일 그룹은 요약에 전체적으로 입력됩니다.
- 요약 입력은 실제 남은 창에 따라 안전하게 분할된 UTF-8이며 출력 상한은 2048 tokens입니다. 빈 요약, 잘림, 도구 호출 또는 요약 예산 초과 등은 캐시에 기록되지 않습니다. 단일 우회는 최대 12개의 다이제스트 호출로 제한되며 동일한 120초 시간 초과가 적용됩니다. 상한에 도달하면 명시적으로 실패하며 무한정 반복되지 않습니다.
- 모델이 처음으로 제한을 초과하는 컨텍스트를 반환하고 아직 텍스트나 도구 호출을 출력하지 않은 경우 추가 감소 후 최대 한 번 재시도됩니다. 예상 크기가 줄어들지 않으면 복구가 즉시 중지됩니다. 기타 모델 오류 및 부분적으로 스트리밍된 출력은 이 복구를 트리거하지 않습니다.
- 요약, 실패한 시도, 취소 시 사용량을 포함하여 획득한 모든 사용량은 동일한 우회 요청에 대해 누적됩니다. Provider는 사용량이 반환되지 않은 경우에도 0만 기록할 수 있으며 추정치를 실제 사용량으로 위장할 수 없습니다.

## 지속성과 인터페이스

`side_question_sessions.memory`는 이전 Q&A 다이제스트, 덮어쓴 ordinal 및 스냅샷 ID로 캐시된 기본 컨텍스트 다이제스트를 저장합니다. `side_question_requests.context_info` 준비 단계, 실제 재생 그룹 수, 요약 사용량 및 예상 예산을 저장합니다.

다이제스트는 원래 요청이 계속 실행 중이고 정리된 버전이 일치하는 동안에만 저장됩니다. 지우면 캐시도 지워지고, 늦게 쓰기해도 정리된 데이터가 복원되지 않습니다. 새 스냅샷은 이전 스냅샷 다이제스트를 재사용하지 않습니다. 요약 필드는 v3 작업 아카이브에 저장됩니다. 이전 v3 누락 필드를 복원할 때 빈 개체를 채우면 v1/v2가 계속 호환됩니다.

POST는 먼저 요청을 수락하고 반환하며 준비 및 압축은 백그라운드에서 수행되며 액세스 잠금이나 데이터베이스 트랜잭션을 보유하지 않습니다. SSE/ 기록에는 준비, Q&A, 압축 복사 및 답변 단계가 표시됩니다. 압축 실패는 바이패스 요청의 실패 최종 상태로 저장됩니다. 프런트 엔드는 오류를 유지하고 입력 상자를 차단하기 위한 부동 알림이 필요 없이 이 실패한 문제의 초안을 복원합니다. 기록 폴링에서는 더 이상 제출 오류가 지워지지 않습니다.
